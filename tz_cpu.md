# ТЗ: минимальный 4-битный микропроцессор на Verilog

## 1. Цель проекта

Разработать максимально простой учебный микропроцессор на **Verilog HDL**, предназначенный для реализации на FPGA.

Процессор должен иметь:

* 8-битную адресную шину;
* 8-битную шину данных памяти только на чтение;
* 4-битную внутреннюю шину данных;
* два 4-битных регистра общего назначения;
* 8-битный счётчик команд `PC`;
* два флага состояния: `C` и `V`;
* два 4-битных внешних I/O-порта;
* минимальную ALU;
* минимальный набор инструкций;
* инструкции фиксированной длины — 8 бит.

Главный приоритет проекта — **простота аппаратной реализации**, а не производительность или расширяемость.

# 2. Архитектура

## 2.1. Разрядность

| Параметр                   |    Значение |
|----------------------------|------------:|
| Адрес                      |       8 бит |
| Инструкция                 |       8 бит |
| Данные CPU                 |      4 бита |
| Регистры общего назначения |      4 бита |
| PC                         |       8 бит |
| Память                     | 256 × 8 бит |
| I/O-порты                  |           2 |
| Ширина I/O                 |      4 бита |

---

# 3. Регистры

Процессор содержит следующие регистры:

```text
PC  — 8 бит
R0  — 4 бита
R1  — 4 бита
IR  — 8 бит
C   — 1 бит
V   — 1 бит
```

## 3.1. PC

`PC` — адрес текущей инструкции.

После выборки инструкции:

```text
PC = PC + 1
```

`PC` должен корректно переходить:

```text
0xFF -> 0x00
```

При выполнении относительного перехода значение `PC` изменяется относительно текущего значения.

---

## 3.2. R0 и R1

Два регистра общего назначения:

```text
R0[3:0]
R1[3:0]
```

Оба регистра полностью равноправны.

---

## 3.3. Флаги

### C — Carry/Borrow

Используется для:

* переноса при `ADD`;
* заёма при `SUB`;
* условного перехода `JC`.

Для `ADD`:

```text
C = carry из bit 3
```

Для `SUB`:

```text
C = 1, если произошёл borrow
```

### V — signed overflow

Используется для определения переполнения знакового 4-битного числа.

Диапазон signed:

```text
-8 ... +7
```

Флаг `V` изменяется только арифметическими операциями `ADD` и `SUB`.

---

# 4. Модель памяти

Память подключается снаружи процессора.

Интерфейс:

```verilog
output wire [7:0] mem_addr;
input  wire [7:0] mem_data;
```

Процессор **никогда не записывает память**.

Запись:

```text
CPU -> MEMORY
```

отсутствует.

Чтение:

```text
CPU <- MEMORY
```

используется для получения инструкций.

Размер адресного пространства:

```text
256 байт
```

---

# 5. Формат инструкции

Все инструкции имеют длину **8 бит**.

Общий формат:

```text
7       4 3       0
+---------+---------+
| opcode  | operand |
+---------+---------+
   4 bit     4 bit
```

То есть:

```verilog
opcode  = instruction[7:4];
operand = instruction[3:0];
```

**Важно:** immediate/operand всегда находится в **младших 4 битах** инструкции.

Не использовать старшие 4 бита для передачи immediate.

---

# 6. ISA

Использовать следующие 16 opcode.

| Opcode | Mnemonic   | Описание                |
|--------|------------|-------------------------|
| `0x0`  | `NOP`      | ничего не делать        |
| `0x1`  | `LDI0`     | `R0 = immediate`        |
| `0x2`  | `LDI1`     | `R1 = immediate`        |
| `0x3`  | `ADD`      | `R0 = R0 + R1`          |
| `0x4`  | `SUB`      | `R0 = R0 - R1`          |
| `0x5`  | `AND`      | `R0 = R0 & R1`          |
| `0x6`  | `XOR`      | `R0 = R0 ^ R1`          |
| `0x7`  | `JMP`      | относительный переход   |
| `0x8`  | `JC`       | переход при `C=1`       |
| `0x9`  | `JV`       | переход при `V=1`       |
| `0xA`  | `IN`       | чтение I/O-порта в `R0` |
| `0xB`  | `OUT`      | запись `R0` в I/O-порт  |
| `0xC`  | `MOV01`    | `R0 = R1`               |
| `0xD`  | `MOV10`    | `R1 = R0`               |
| `0xE`  | `HALT`     | останов процессора      |
| `0xF`  | `RESERVED` | зарезервировано         |

---

# 7. LDI

## LDI0

```text
0x1N
```

где:

```text
N = immediate[3:0]
```

Операция:

```text
R0 = instruction[3:0]
```

Примеры:

```text
LDI0 0
LDI0 5
LDI0 15
```

Машинные коды:

```text
0x10
0x15
0x1F
```

---

## LDI1

```text
0x2N
```

Операция:

```text
R1 = instruction[3:0]
```

Примеры:

```text
LDI1 0
LDI1 5
LDI1 15
```

Машинные коды:

```text
0x20
0x25
0x2F
```

---

# 8. ADD

```text
opcode = 0x3
```

Операция:

```text
R0 = R0 + R1
```

Результат:

```text
R0 = result[3:0]
C  = result[4]
```

`V` вычисляется как signed overflow.

Формула:

```text
V = (~(R0[3] ^ R1[3])) & (result[3] ^ R0[3])
```

Предыдущие значения `C` и `V` заменяются новыми.

---

# 9. SUB

```text
opcode = 0x4
```

Операция:

```text
R0 = R0 - R1
```

`C=1`, если при вычитании произошёл borrow.

`V` — signed overflow.

Формула:

```text
V = (R0[3] ^ R1[3]) & (result[3] ^ R0[3])
```

Предыдущие значения `C` и `V` заменяются новыми.

---

# 10. Логические операции

## AND

```text
opcode = 0x5

R0 = R0 & R1
```

## XOR

```text
opcode = 0x6

R0 = R0 ^ R1
```

Логические операции:

* не изменяют `C`;
* не изменяют `V`.

---

# 11. Относительные переходы

Все переходы используют `instruction[3:0]` как **signed 4-bit displacement**.

Диапазон:

```text
-8 ... +7
```

Представление:

```text
0x0 =  0
0x1 = +1
0x2 = +2
...
0x7 = +7

0x8 = -8
0x9 = -7
...
0xF = -1
```

Displacement необходимо рассматривать как знаковое число в дополнительном коде.

---

# 12. JMP

```text
opcode = 0x7
```

Операция:

```text
PC = PC + signed(instruction[3:0])
```

Переход выполняется безусловно.

Пример:

```text
JMP +3
```

код:

```text
0x73
```

Пример:

```text
JMP -1
```

код:

```text
0x7F
```

---

# 13. JC

```text
opcode = 0x8
```

Если:

```text
C == 1
```

то:

```text
PC = PC + signed(instruction[3:0])
```

Если:

```text
C == 0
```

переход не выполняется.

---

# 14. JV

```text
opcode = 0x9
```

Если:

```text
V == 1
```

то:

```text
PC = PC + signed(instruction[3:0])
```

Иначе переход не выполняется.

---

# 15. I/O

Процессор имеет два внешних 4-битных порта:

```text
PORT0
PORT1
```

Интерфейс:

```verilog
input  wire [3:0] port0_in;
output wire [3:0] port0_out;

input  wire [3:0] port1_in;
output wire [3:0] port1_out;
```

---

# 16. IN

Opcode:

```text
0xA
```

`instruction[3:0]` используется для выбора порта.

Разрешённые значения:

```text
operand = 0 -> PORT0
operand = 1 -> PORT1
```

Операция:

```text
IN PORT0 -> R0
IN PORT1 -> R0
```

Примеры:

```text
0xA0 = IN PORT0
0xA1 = IN PORT1
```

Для остальных значений operand поведение должно быть определено как `NOP` либо явно отмечено как invalid instruction.

Рекомендуемый вариант:

```text
operand > 1 -> NOP
```

---

# 17. OUT

Opcode:

```text
0xB
```

Источник всегда:

```text
R0
```

Выбор порта:

```text
operand = 0 -> PORT0
operand = 1 -> PORT1
```

Примеры:

```text
0xB0 = OUT PORT0, R0
0xB1 = OUT PORT1, R0
```

Значения operand `2..15` трактовать как `NOP`.

---

# 18. MOV

## MOV01

```text
opcode = 0xC

R0 = R1
```

## MOV10

```text
opcode = 0xD

R1 = R0
```

Operand для этих инструкций игнорируется.

---

# 19. HALT

```text
opcode = 0xE
```

После выполнения:

```text
CPU halted
```

В состоянии `HALT`:

* `PC` не изменяется;
* регистры не изменяются;
* флаги не изменяются;
* I/O не выполняется;
* память не читается.

Для выхода из `HALT` использовать внешний сигнал:

```verilog
input wire reset;
```

После reset процессор начинает выполнение с адреса `0x00`.

---

# 20. RESERVED

```text
opcode = 0xF
```

Зарезервировано для будущего расширения.

На текущем этапе:

```text
RESERVED = NOP
```

Процессор не должен зависать или переходить в неопределённое состояние.

---

# 21. Цикл выполнения

Использовать простую двухфазную FSM:

```text
FETCH
  |
  v
EXECUTE
  |
  v
FETCH
```

## FETCH

В состоянии `FETCH`:

```text
mem_addr = PC
```

Получить:

```text
IR = mem_data
```

Затем:

```text
PC = PC + 1
```

После этого перейти в `EXECUTE`.

---

## EXECUTE

Декодировать:

```verilog
opcode  = IR[7:4];
operand = IR[3:0];
```

Выполнить операцию.

После выполнения:

```text
EXECUTE -> FETCH
```

---

# 22. Важное требование к PC-relative переходам

`PC` должен быть увеличен на единицу **до выполнения инструкции перехода**.

То есть переход вычисляется относительно адреса следующей инструкции.

Пример:

```text
0x10: JMP +2
0x11: ...
0x12: ...
0x13: ...
```

После FETCH:

```text
PC = 0x11
```

После `JMP +2`:

```text
PC = 0x13
```

Это необходимо зафиксировать именно так.

---

# 23. Reset

При активном reset:

```text
PC = 0x00
R0 = 0x0
R1 = 0x0
C  = 0
V  = 0
HALT = 0
IR = 0x00
```

После снятия reset процессор начинает:

```text
FETCH @ 0x00
```

Reset сделать синхронным или асинхронным в соответствии с выбранным стилем Verilog, но поведение должно быть
документировано.

Для простоты рекомендуется:

```verilog
always @(posedge clk or posedge reset)
```

с асинхронным reset.

# 25. ALU

ALU должна быть отдельным модулем.

Интерфейс примерно:

```verilog
module alu (
    input  wire [3:0] a,
    input  wire [3:0] b,
    input  wire [2:0] op,

    output reg  [3:0] result,
    output reg        carry,
    output reg        overflow
);
```

Поддержать:

```text
ADD
SUB
AND
XOR
```

Для логических операций:

```text
carry     = 0 или сохраняется внешней логикой
overflow  = 0 или сохраняется внешней логикой
```

Предпочтительно, чтобы ALU не хранила состояние. Флаги должны храниться в CPU.

---

# 26. Decoder

Decoder должен преобразовывать:

```text
opcode
operand
```

в управляющие сигналы.

Не использовать сложную микропрограммную архитектуру.

Обычный:

```verilog
case (opcode)
```

является предпочтительным решением.

---

# 27. I/O

I/O должен быть простым.

Для `OUT` желательно использовать регистр состояния порта:

```text
port0_out_reg
port1_out_reg
```

При выполнении:

```text
OUT PORT0
```

в:

```text
port0_out_reg
```

записывается:

```text
R0
```

Аналогично для PORT1.

Для `IN` значение соответствующего входа непосредственно загружается в `R0`.

---

# 28. Синхронность I/O

`OUT` должен изменять соответствующий выход на фронте `clk`.

`IN` должен считывать значение входного порта во время выполнения инструкции.

---

# 29. Что НЕ нужно реализовывать

На текущем этапе запрещено добавлять:

* стек;
* SP;
* CALL/RET;
* прерывания;
* DMA;
* MMU;
* кеш;
* pipeline;
* многозадачность;
* privileged mode;
* аппаратное умножение;
* аппаратное деление;
* память для записи;
* сложную систему адресации;
* дополнительные регистры;
* дополнительные флаги без необходимости.

Процессор должен оставаться минимальным.

---

# 30. Требования к коду

Использовать обычный synthesizable Verilog.

Не использовать:

* SystemVerilog-специфичные конструкции без необходимости;
* `initial` для логики процессора;
* задержки `#`;
* несинтезируемые конструкции;
* тристейт внутри ядра;
* сложные генераторы.

Код должен корректно работать как в симуляторе, так и после синтеза FPGA.

# 36. Критерии готовности

Проект считается завершённым, если:

1. Все RTL-модули компилируются без ошибок.
2. Testbench компилируется.
3. Все автоматические тесты проходят.
4. Нет latch в синтезируемой логике.
5. Нет неопределённых (`X`) состояний после reset.
6. `PC` корректно работает по модулю 256.
7. Все инструкции ISA реализованы.
8. `RESERVED` не приводит к зависанию CPU.
9. Память используется только для чтения.
10. I/O работает с шириной 4 бита.
11. Immediate берётся исключительно из `instruction[3:0]`.
12. Relative displacement интерпретируется как signed 4-bit.
13. Код синтезируется обычным FPGA synthesis tool.
14. Архитектура не содержит функций, отсутствующих в данном ТЗ.

# 37. Ограничение на расширения

Coding-модель **не должна самостоятельно расширять ISA или архитектуру**.

Если при реализации обнаруживается архитектурная неоднозначность:

1. сначала использовать это ТЗ как источник истины;
2. не добавлять новые инструкции;
3. не добавлять новые регистры;
4. не менять формат инструкции;
5. не менять ширину шин;
6. не менять семантику `C` и `V`.

Если без изменения архитектуры реализовать требование невозможно, необходимо явно сообщить о проблеме вместо
самостоятельного изменения ISA.

# 39. Главный принцип реализации

Процессор должен быть реализован максимально просто.

Предпочтительная архитектура:

```text
             +-------------+
 memory --->| instruction |
             |   decoder   |
             +------+------+
                    |
             +------+------+
             |             |
           R0/R1           PC
             |             |
             v             |
          +------+         |
          | ALU  |         |
          +--+---+         |
             |             |
             v             |
          R0 / flags       |
                           |
             +-------------+
             |
             v
          I/O ports
```

Не оптимизировать архитектуру преждевременно.

Главная цель первой версии:

**минимальный, полностью работающий и легко понимаемый CPU, который можно синтезировать на FPGA и исследовать в
симуляторе.**
