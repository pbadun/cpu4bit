# 4-битный процессор на Verilog

Минимальный учебный процессор с фиксированными 8-битными инструкциями, реализованный на синтезируемом Verilog. Проект
включает RTL-ядро, автоматизированный testbench и двухпроходный ассемблер Python для подготовки образов памяти.

Процессор предназначен для изучения базовых принципов работы CPU: выборки и декодирования инструкций, работы ALU,
флагов, относительных переходов, I/O и конечного автомата. Ядро не зависит от конкретной платы и может быть подключено к
внешней read-only памяти инструкций в симуляции или FPGA-проекте.

## Возможности

- адресное пространство инструкций: 256 байт;
- внешняя память инструкций: 256 x 8 бит, только чтение со стороны CPU;
- 8-битные инструкции фиксированной длины;
- 4-битный тракт данных;
- два регистра общего назначения: `R0` и `R1`;
- 8-битный счётчик команд `PC`;
- флаги `C` и `V`;
- два 4-битных входа и два 4-битных выхода I/O;
- отдельная combinational ALU;
- двухфазный цикл `FETCH -> EXECUTE`;
- `HALT` с сохранением архитектурного состояния до сброса;
- асинхронный active-high reset;
- автоматическая проверка RTL в Icarus Verilog;
- ассемблер без сторонних Python-пакетов.

Проект сознательно не реализует стек, `CALL`/`RET`, прерывания, запись в память, pipeline, умножение и другие расширения
ISA.

## Архитектура

```text
                 +-----------------------+
 read-only memory| instruction fetch     |
 mem_data <------| PC, IR, FETCH/EXECUTE |
                 +-----------+-----------+
                             |
                             v
                 +-----------+-----------+
                 | decoder + control FSM |
                 +-----+-----------+-----+
                       |           |
                       v           v
                  +----+----+   +--+-----+
                  | R0 / R1 |   | PC     |
                  +----+----+   +--------+
                       |
                       v
                  +----+----+
                  |   ALU   |
                  +----+----+
                       |
                       v
                 flags and I/O
```

Во время `FETCH` адрес памяти получает текущий `PC`, байт `mem_data` загружается в `IR`, после чего `PC` увеличивается
на единицу. Относительные переходы вычисляются от адреса следующей инструкции. Все изменения `PC` выполняются с 8-битным
переполнением.

## Быстрый старт

### Требования

Для симуляции:

- Python 3.8 или новее;
- Icarus Verilog: `iverilog` и `vvp`;
- `make` желателен, но не обязателен.

Для работы ассемблера внешние Python-пакеты не нужны.

### Симуляция RTL

Из корня репозитория:

```sh
mkdir -p verilog/sim
iverilog -g2005 -Wall -s tb_cpu \
  -o verilog/sim/cpu_sim \
  verilog/rtl/alu.v \
  verilog/rtl/decoder.v \
  verilog/rtl/cpu.v \
  verilog/tb/tb_cpu.v

vvp verilog/sim/cpu_sim
```

При установленном `make` можно выполнить то же самое короче:

```sh
make -C verilog sim
```

Успешный запуск завершается строкой `ALL TESTS PASSED`.

### Сборка программы ассемблером

Проверить исходник без записи результата:

```sh
python3 copmiler/cpu_asm.py copmiler/examples/arithmetic.asm --check --list
```

Собрать все поддерживаемые форматы:

```sh
python3 copmiler/cpu_asm.py copmiler/examples/arithmetic.asm \
  --format all \
  --output copmiler/generated/arithmetic.bin
```

Будут созданы:

```text
copmiler/generated/arithmetic.bin  # полный образ памяти, 256 байт
copmiler/generated/arithmetic.mem  # файл для Verilog $readmemh
copmiler/generated/arithmetic.hex  # Intel HEX
```

Собрать все примеры можно командой:

```sh
make -C copmiler
```

Без `make` каждый пример собирается прямым вызовом `python3 copmiler/cpu_asm.py`; полный список параметров выводит
`python3 copmiler/cpu_asm.py --help`.

## Пример программы

Файл `copmiler/examples/arithmetic.asm` вычисляет `(5 + 3) + 1`, копирует результат в `R1`, выводит его в `PORT0` и
останавливает процессор:

```asm
; (5 + 3) + 1
LDI0  5
LDI1  3
ADD
LDI1  1
ADD
MOV10
OUT   PORT0
HALT
```

Машинный код:

```text
15 23 30 21 30 D0 B0 E0
```

После завершения:

```text
R0      = 9
R1      = 9
PORT0   = 9
halted  = 1
```

`MOV10` здесь выбран намеренно: по ISA он копирует `R0` в `R1`. В исходном техническом задании в контрольной программе
указана команда `MOV01`, но при заявленном результате `R1 = 9` требуется именно `MOV10`; реализация и примеры следуют
формальному описанию ISA.

## Набор инструкций

Каждая инструкция имеет формат:

```text
7       4 3       0
+---------+---------+
| opcode  | operand |
+---------+---------+
```

`operand` всегда занимает младшие 4 бита. Для `LDI` это immediate `0..15`; для переходов — знаковое смещение `-8..+7`;
для `IN`/`OUT` — номер порта `0` или `1`.

| Opcode | Mnemonic   | Операция                           |
|-------:|------------|------------------------------------|
|  `0x0` | `NOP`      | Нет операции                       |
|  `0x1` | `LDI0`     | `R0 = operand`                     |
|  `0x2` | `LDI1`     | `R1 = operand`                     |
|  `0x3` | `ADD`      | `R0 = R0 + R1`, обновить `C` и `V` |
|  `0x4` | `SUB`      | `R0 = R0 - R1`, обновить `C` и `V` |
|  `0x5` | `AND`      | `R0 = R0 & R1`                     |
|  `0x6` | `XOR`      | `R0 = R0 ^ R1`                     |
|  `0x7` | `JMP`      | `PC = PC + signed(operand)`        |
|  `0x8` | `JC`       | Переход при `C = 1`                |
|  `0x9` | `JV`       | Переход при `V = 1`                |
|  `0xA` | `IN`       | Выбранный входной порт -> `R0`     |
|  `0xB` | `OUT`      | `R0` -> выбранный выходной порт    |
|  `0xC` | `MOV01`    | `R0 = R1`                          |
|  `0xD` | `MOV10`    | `R1 = R0`                          |
|  `0xE` | `HALT`     | Остановить выполнение              |
|  `0xF` | `RESERVED` | Обрабатывается как `NOP`           |

`ADD` устанавливает `C` при переносе из старшего 4-битного разряда, а `SUB` устанавливает `C` при заёме. `V` отражает
переполнение знакового 4-битного диапазона `-8..+7`. Логические операции `AND` и `XOR` флаги не изменяют.

Для `IN` и `OUT` допустимы только `PORT0` (`0`) и `PORT1` (`1`). Зарезервированный opcode и недопустимый номер порта не
выполняют I/O и не изменяют регистры или флаги; `PC` при этом продолжает увеличиваться, и выполнение идёт дальше.

Подробное описание кодировок, формул флагов и относительных переходов находится
в [verilog/docs/ISA.md](verilog/docs/ISA.md).

## Ассемблер

Ассемблер находится в каталоге [`copmiler/`](copmiler/). Он поддерживает:

- метки и регистронезависимые мнемоники;
- комментарии `;`, `#` и `//`;
- `.org`, `.db`, `.fill`/`.space` и `.equ`;
- десятичные, шестнадцатеричные и двоичные числа;
- относительные переходы по меткам;
- абсолютные цели в форме `JMP @LABEL`;
- проверки диапазонов immediate, смещений, адресов и портов;
- вывод `.bin`, `.mem` и Intel HEX.

Пример перехода по метке:

```asm
loop:
    OUT PORT0
    JMP loop
```

Смещение перехода рассчитывается относительно уже увеличенного `PC`, как того требует реализация процессора.

## Тестирование

Проверить ассемблер:

```sh
python3 -m unittest discover -s copmiler/tests -v
```

или:

```sh
make -C copmiler test
```

Тесты покрывают кодирование инструкций, директивы, signed relative branches, границы памяти, проверки ошибок, CLI и все
корректные примеры. `examples/invalid_branch.asm` используется как отрицательный тест и должен завершаться ошибкой.

Полный RTL-тест запускается командой `make -C verilog sim` и проверяет reset, ALU и флаги, MOV, переходы, I/O, `HALT`,
зарезервированные инструкции, переполнение `PC` и контрольную программу.

## Использование в FPGA-проекте

RTL написан на обычном синтезируемом Verilog и не использует `initial` в логике ядра. Для FPGA необходимо подключить
внешнюю ROM инструкций, задать начальный образ памяти и добавить board-specific wrapper с тактовым генератором, reset,
портами и ограничениями пинов. Готовые pin constraints для конкретной платы в репозитории не поставляются.
