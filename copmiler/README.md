# Ассемблер 4-битного CPU

`cpu_asm.py` преобразует текстовые программы на ISA из `../verilog/docs/ISA.md` в байты инструкции для процессора из
`../verilog/rtl/cpu.v`. Компилятор не добавляет новые команды, регистры или режимы адресации: формат инструкции остаётся
`opcode[7:4] | operand[3:0]`, размер образа памяти — 256 байт.

## Структура

```text
copmiler/
├── cpu_asm.py                 # ассемблер и CLI
├── Makefile                   # сборка примеров и запуск тестов
├── README.md                  # эта документация
├── examples/
│   ├── arithmetic.asm         # арифметика, MOV, OUT, HALT
│   ├── blink.asm              # программное мигание PORT0
│   ├── pwm.asm                # программная ШИМ на PORT0
│   ├── counter.asm            # счётчик 0..15 и останов по C
│   ├── io_echo.asm            # копирование PORT0 -> PORT1
│   ├── flags.asm              # JC и JV по C/V
│   └── invalid_branch.asm     # намеренно ошибочная программа
└── tests/
    └── test_cpu_asm.py
```

Каталог `generated/` создаётся при сборке. В него записываются `.bin`, `.mem` и `.hex` для каждого корректного примера.

## Требования

- Python 3.8 или новее;
- внешние Python-пакеты не требуются;
- `make` необязателен.

## Синтаксис исходника

Мнемоники, имена меток и имена портов не зависят от регистра. Разделителем операнда может быть пробел или запятая.

```asm
label:      LDI0 5      ; комментарий до конца строки
            ADD
loop:       JMP loop
```

Поддерживаются комментарии `;`, `#` и `//`. Поддерживаются директивы:

- `.org address` — установить текущий адрес программы;
- `.db byte0, byte1, ...` — записать сырые байты;
- `.fill count [, value]` или `.space count [, value]` — заполнить память;
- `.equ NAME = expression` или `.equ NAME, expression` — числовая константа.

Числа принимаются в десятичном, шестнадцатеричном (`0x`) и двоичном (`0b`) виде. Immediate для `LDI0`/`LDI1` обязан
находиться в диапазоне `0..15`. `IN`/`OUT` принимают только `PORT0`/`0` и `PORT1`/`1`.

Команды `NOP`, `ADD`, `SUB`, `AND`, `XOR`, `MOV01`, `MOV10` и `HALT` не имеют операндов. `RESERVED` намеренно не
является мнемоникой; при необходимости сырой байт можно записать через `.db 0xF0`.

## Переходы и проверки

Для `JMP`, `JC` и `JV` числовой операнд трактуется как signed displacement, а не как абсолютный адрес:

```asm
JMP +2      ; 0x72
JC  -1      ; 0x8F
JV  label   ; assembler вычислит displacement
```

Адрес цели для метки рассчитывается по правилу процессора:

```text
target = label_address
displacement = target - (address_текущей_инструкции + 1)
```

Допустимый диапазон displacement: `-8..+7`. Ассемблер проверяет:

- существование метки;
- диапазон signed displacement;
- адрес цели `0x00..0xFF`;
- отсутствие выхода за память при numeric displacement;
- дублирование меток;
- размер программы и директив;
- диапазоны immediate, raw bytes и I/O-портов.

Опционально можно явно указать абсолютную цель через `@`:

```asm
JMP @START
JC  @0x20
```

Это только синтаксическая форма; в машинный код всё равно записывается обычный 4-битный signed operand ISA.

При ошибке компилятор печатает файл, номер строки и причину, возвращает код `1` и не записывает результат.

## Команды запуска

Проверка без создания файла:

```sh
cd /workspace/copmiler
python3 cpu_asm.py examples/arithmetic.asm --check --list
```

Создание raw-образа памяти:

```sh
python3 cpu_asm.py examples/blink.asm -o generated/blink.bin
```

Создание всех форматов:

```sh
python3 cpu_asm.py examples/pwm.asm \
  --format all --output generated/pwm.bin
```

Будут созданы:

```text
generated/pwm.bin   # 256 байт, порядок соответствует адресам 0x00..0xFF
generated/pwm.mem   # текст для Verilog $readmemh
generated/pwm.hex   # Intel HEX
```

По умолчанию raw `.bin` содержит полный образ из 256 байт; незаполненные адреса заполняются `0x00`. Флаг `--compact`
убирает хвостовые байты заполнения. Флаг `--origin 0x10` задаёт начальный PC, а `--padding 0xFF` меняет байт заполнения.

Для Verilog-тестовой памяти можно использовать текстовый образ:

```verilog
reg [7:0] memory [0:255];

initial begin
    $readmemh("generated/arithmetic.mem", memory);
end
```

Путь в `$readmemh` задаётся относительно каталога, из которого запускается симулятор.

## Примеры машинного кода

### Арифметика

```asm
LDI0 5
LDI1 3
ADD
LDI1 1
ADD
MOV10
OUT PORT0
HALT
```

Компактный машинный код:

```text
15 23 30 21 30 D0 B0 E0
```

Результат: `R0 = 9`, `R1 = 9`, `PORT0 = 9`, `halted = 1`.

### Мигание

`examples/blink.asm` переключает `PORT0` между `0x00` и `0x0F`:

```text
10 B0 00 00 1F B0 00 78
```

`JMP BLINK` имеет крайнее допустимое displacement `-8`; цикл не использует команд, отсутствующих в ISA.

### ШИМ

`examples/pwm.asm` формирует программную ШИМ 50%: высокая фаза — `LDI0 15`, `OUT`, `NOP`, низкая фаза — `LDI0 0`, `OUT`,
`JMP`:

```text
10 1F B0 00 10 B0 7A
```

Частоту и duty cycle можно менять числом инструкций в фазах, пока переход остаётся в диапазоне `-8..+7`.

### Счётчик

`examples/counter.asm` выводит последовательность `0..15`, использует `C` после переполнения `ADD` и завершается `HALT`:

```text
10 B0 21 30 81 7B E0
```

### I/O echo

`examples/io_echo.asm` бесконечно копирует `PORT0` в `PORT1`:

```text
A0 B1 7D
```

### Флаги

`examples/flags.asm` отдельно проверяет ветвление по `C` и по `V`:

```text
1F 21 30 82 00 00 17 21 30 92 00 00 10 B0 E0
```

## Тесты

```sh
cd /workspace/copmiler
python3 -m unittest discover -s tests -v
```

Тесты проверяют кодирование всех групп команд, signed relative branches, абсолютные цели, границы памяти, immediate,
I/O-порты, директивы, дублирование меток, CLI и все корректные примеры. `examples/invalid_branch.asm` используется как
отрицательный тест и обязан завершаться ошибкой.
